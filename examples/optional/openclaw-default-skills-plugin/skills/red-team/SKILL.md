# Red Team

Adversarially test a plan, design, workflow, or system for failure modes, abuse paths, and unsafe assumptions.

## Use When
- The user wants to stress-test an idea or system.
- Safety, abuse, or failure under pressure matters.
- The optimistic plan needs an adversarial pass.

## Default Workflow
1. Define the target, trust boundaries, and success conditions.
2. Model likely attacker, user-error, and environment-failure paths.
3. Prioritize realistic high-impact weaknesses.
4. Return attack paths, mitigations, and detection ideas.

## Output
- Return a concise, decision-ready result with assumptions, risks, and recommended next steps.
- If evidence is weak or missing, say so explicitly instead of over-claiming.
